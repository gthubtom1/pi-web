# 全项目审查委托书（交给一个"陌生人"测试工程师）

> 用法：新开一个会话，把本文件整份发过去，或直接说
> **"读 docs/AUDIT-BRIEF.md，按里面的规则把整个项目审查一遍，输出报告。"**
> 目的：让审查者**不依赖作者的说法、不靠"看代码猜答案"**，而是用可复现的证据把项目过一遍。

---

## 0. 你的身份与纪律（先读，违反即作废）

你是一名**外部 QA / 安全测试工程师**，刚从 GitHub 拿到这个仓库，**不认识作者，也没有参加过开发**。

1. **不要相信任何已有报告**（包括 `docs/FORK-NOTES.md`、`docs/agents/*.md`、CHANGELOG、commit message）。它们只是"待验证的声明"。逐条自己验。
2. **不要用"读代码然后判断应该没问题"结案。** 每个结论必须给**证据**：命令输出、测试结果、DOM 尺寸、截图、请求/响应、会话文件内容。区分 `[实测]` / `[读码]` / `[推测]`，推测必须标注并说明如何验证。
3. **先报告，后修**。审查期间**不要改代码**（除非用户明确说"顺手修"）。发现问题只记录。
4. **不扩张范围**：不重构、不升级依赖、不加功能。目标是"查清楚"，不是"做漂亮"。
5. **诚实**：没验证的写"未验证"，失败要写失败。禁止用"应该""看起来""一般来说"糊过去。
6. 项目规则以 `AGENTS.md` 为准（含"不要 `next build` 污染 dev"、Safari 16.2 基线、扩展兼容原则等）。

## 1. 交付物（必须齐全）

### D1. 覆盖矩阵（先建，后填）
把项目**所有面向用户的表面**列成表，每行给状态：`✅通过 / ⚠️有问题 / ❌未测`，并写证据。至少覆盖：

- **每一个 API 路由**（`app/api/**`）：方法、入参校验、鉴权/host 校验、错误码、超时、缓存头
- **每一个设置分区**（常规 / 远程访问 / 人设与规则 / 模型 / 技能 / 子代理 / 插件 / MCP）：加载、空态、错误态、保存、取消、Escape、焦点
- **每一个新组件**：`PersonaSelector`、`SystemPromptsConfig`、`RemoteAccessSection`、`QrCode`、`AdvisorConfig`，以及被改动的 `ChatInput` / `ChatWindow` / `MessageView` / `SettingsPanel`
- **每一套主题**（浅色/雾青/丁香/暖沙/蔷薇/OpenCode/深色/松夜/暮紫/余烬/岩蓝/OpenCode 暗/高对比×2/Zenburn）：文字对比度、边框可见、卡片/气泡/工具卡/代码块/引用块是否都能区分
- **三语文案**（en / zh-CN / zh-TW）：键集合一致、无硬编码、占位符格式、超长文案不撑破布局
- **断点**：390 / 768 / 1024 / 1280 / 1600 / 手机横屏；键盘弹起时输入框与发送键可用
- **关键流程**：新建会话 → 发消息 → 流式 → 工具调用 → 中止 → 分支/分叉/编辑/回退/只删回复 → 压缩 → 导出 → 删除
- **远程访问**：本机免密、局域网配对码、公网配对码、两码互斥、开关关闭、隧道启停/自检、固定域名（token/主机名保存需确认、换域名生效）
- **MCP / 技能 / 插件 / 子代理 / 终端 / 文件浏览 / CSV 表格 / 图片预览**：打开、失败、超大、越权路径

### D2. 问题清单（按严重度）
每条必须包含：

```
[P1] 标题：一句话说清坏在哪
位置：文件:行号（或组件/路由）
复现：可复制执行的步骤/命令（含 URL、尺寸、输入）
实际：观察到的现象（贴输出/尺寸/截图路径）
期望：应该怎样（引用上游约定或产品目标）
证据：[实测] 命令与输出 / [读码] 具体行
建议：最小修法（不要顺手改）
```

分级：`P0 数据/安全/崩溃` · `P1 功能错、主流程断` · `P2 体验/一致性/边界` · `P3 文案/美观/清理`

### D3. 未验证清单
写明你**没能验证**什么、为什么、需要什么条件（例如"手机关税网络无法模拟"）。

### D4. 结论
一句话：可以发布 / 修完 P0-P1 可发布 / 不建议发布，并列出**阻断项**。

## 2. 方法（照做，不要省）

### 2.1 建立基线（关键，否则会把自己的环境问题算到项目头上）
```bash
git worktree add ../baseline HEAD      # HEAD = 当前已提交版本
# 在 baseline 里跑同样的测试，记下"本来就失败"的清单
```
Windows/Node 24 上已知有一批**环境性失败**（hooks 的绝对路径 import、部分集成测试）。**先在 baseline 复跑**，只有"我们这里失败、baseline 通过"的才算回归。

### 2.2 静态审查（逐文件，不要抽样）
```bash
node_modules/.bin/tsc --noEmit
npm run lint
npm test 2>&1 | tee /tmp/tests.log       # 注意：全量很慢，可分目录批次跑
```
- 对**每一个被改过的文件**：读 diff（`git diff HEAD`），列出改动意图，再验是否达到意图、是否引入副作用。
- 全局搜：
  - 硬编码文案：`grep -rn '[一-龥]' components lib app --include=*.tsx`（排除注释）→ 任何面向用户的字符串必须走 `t()`
  - 死代码：未使用的 i18n 键（三语互查）、未被引用的 CSS 类、`TODO|FIXME|XXX`
  - 密钥：`git diff HEAD | grep -iE 'secret|token|password|sk-'`，以及 `lib/*.ts` 里是否有写死的域名/凭据
  - 每个新路由是否都有 `isApiRequestAllowed`（和 POST 的 `hasJsonContentType`）
  - 客户端代码禁止 lookbehind（Safari 16.2）

### 2.3 运行时审查（必须真起服务，别只看代码）
```bash
npm run dev            # 30141
# 生产构建（这台机器需要更大堆）：
NODE_OPTIONS=--max-old-space-size=9216 npm run build
```
用 Playwright（本机已有 `pi-playwright` 技能）在 **390 / 768 / 1280 / 1600** 四档各走一遍，并且：
- 收集 `console` 报错与失败请求（任何 4xx/5xx 都要能解释）
- 用 `getBoundingClientRect()` 量**重叠/溢出**（不是目测）：控件之间不得重叠、不得越出容器
- 键盘全部走一遍（Tab 顺序、Escape、Enter 发送/Ctrl+Enter、弹窗焦点归还）
- 深色/浅色/高对比各截一张关键界面

### 2.4 压力与边界（这些最容易藏 bug）
- 20+ 个人设卡；200+ 条消息的会话；100+ 文件的目录；10MB 图片；CSV 1 万行
- 超长名称/超长消息/纯 emoji/中文标点/换行/HTML 片段
- 快速连点发送、运行中再发、运行中止、中止后立刻重发
- 会话运行中点回退/删除/分叉；回退到第一条；删掉当前默认人设
- 隧道：未启动就点自检、启动中再点、停止后旧地址访问（应报 Cloudflare 错误，不是崩溃）
- 配对：错误码连试、关闭配对码后再配对、扫码链接重复使用、换主机名后旧地址

### 2.5 一致性审查（"像不像同一个产品"）
- 新面板是否复用 `SettingsUi` 的分区/标题/按钮/开关（不要自造一套）
- 同一操作在不同位置是否用同一文案与同一确认方式
- 新主题是否只影响自己（不得改动其他主题变量）
- 与上游 `agegr/pi-web` 的约定是否被破坏（**禁止给扩展 API 增加 pi-web 专属字段**）

## 3. 本项目**必须重点核对**的具体点（前人踩过）

| 区域 | 要核什么 |
|---|---|
| 输入框 | 卡片宽度是否等于对话列并与之对齐；窄窗口右侧控件是否被挤出；手机上控件是否重叠；`compact` 模式是否仍无边框 |
| 人设选择器 | 新对话显示的是"全局默认"而不是"无人设"；选中的值真的进了 system prompt（取 transcript/payload 证据）；零人设时是否隐藏 |
| 人设注入 | `every-turn` 与 `cached` 两种模式都只出现**一个** `<personality>`；与 `PERSONALITY.md` 扩展共存时不打架；规则仍全局 |
| 人设面板 | 导入按钮在方框上方；方框撑满到底、滚动条隐藏、一行两个；卡片再多不把"全局"挤走 |
| 回退 / 只删回复 | 确认策略（整轮有工具才确认）；截断后不产生悬空 `parentId`/`firstKeptEntryId`；回填草稿剥掉工作台横幅 |
| 顾问 | 默认关；打断后不递归；模型解析不到时不偷偷用主模型；取消能立刻停 |
| 远程访问 | 本机 `127.0.0.1` 免密；局域网/公网**两套码互斥**；qr 的 secret 只在 `#` 片段；关闭公网码有警告；token/主机名**保存需二次确认**、代码里搜不到域名 |
| 隧道 | 启动状态机（下载/连接/运行/错误）、cloudflared 退出后行为、自检结论与 DNS 失败提示 |
| i18n | 三语键完全一致；无硬编码；新加主题名三语齐全 |
| 主题 | 15 套逐个看：正文/次要文字对比度、边框、卡片、代码块、引用块、工具卡、用户气泡是否可区分 |
| 会话 | 流式渲染只重绘当前块；长思考分片；工具卡折叠；压缩提示；导出 HTML；删除后不复活 |
| 安全面 | 每个 `/api/**` 的 host/origin 校验；`/api/files` 的允许根；配对码限流；日志里不得出现 token/密钥/密码 |
| 文档 | `README*.md` / `docs/agents/*` / `FORK-NOTES` 与实际行为是否一致（尤其默认值、命令、端口、鉴权方式） |
